# Ener Bot Studio — ขาย AI bot LINE OA ให้ร้านค้า (white-label)

สถานะ: ไอเดีย + สังเคราะห์ 14 ส.ค. 2026 · รอกบเคาะ ยังไม่เริ่ม code

## Positioning (กบย้ำ 14 ส.ค.)

**"ร้านไม่ต้องทำอะไรเลย"** — done-for-you ไม่ใช่ DIY tool: เราเซ็ตให้ทั้งหมด ร้านแค่ส่งข้อมูล
(รูปสินค้า ราคา เลขบัญชี) ทางแชท · **ตอบถูกแน่** (KB-only ไม่เดา) · **โทนเหมือนคนจริง**
ไม่ใช่ bot แข็ง ๆ — จุดนี้ ener-scan มี persona/wording engine ที่ทำมาหนักแล้ว ได้เปรียบคู่แข่ง
→ dashboard ให้ร้านทำเองเลื่อนไปเฟสท้าย ๆ ได้เลย ช่วงแรก admin เราเซ็ตให้ทุกร้าน

## สัญญาณตลาด (กบ 14 ส.ค.)

- มีลูกค้าอยากให้ทำ **เยอะ** — เห็น ener-scan ตอบแล้วบอกว่า "ไม่เหมือน bot เหมือนคน"
- pain ที่ลูกค้าบ่น: bot ทั่วไปพอตอบไม่ได้ชอบบอก "ติดต่อแอดมิน" — คนไม่อยากคุยกับ bot แบบนั้น
  → ระบบเราต้องออกแบบให้ "ไม่ตัน" เป็น requirement อันดับต้น ไม่ใช่แค่ handover
- use case ที่ถูกขอเป็น**ข้อแรกคือ เลื่อนนัด** (reschedule) → เทมเพลตบริการ/จองคิว
  อาจต้องขยับขึ้นมาเป็นเทมเพลตแรกแทนร้านขายของ

## ไอเดียหลัก

เอา "แชสซี" ของ ener-scan (LINE webhook + AI ตอบ + เช็คสลิป + quota + สรุปยอด) มาแยกเป็นระบบใหม่
ขายให้ร้านค้าที่ใช้ LINE OA: ร้านเสื้อผ้า ร้านขายของ ร้านบริการ ให้ bot ตอบลูกค้า รับออเดอร์
เช็คสลิปโอนเงิน ตอบ FAQ และสรุปยอดขายส่งเข้า LINE เจ้าของร้านทุกวัน
คิดค่าบริการรายเดือนตามจำนวนข้อความที่ AI ตอบ

## 1) Code เดิมเอามาใช้ได้ไหม — ได้ แต่อย่า fork ทั้งก้อน

โค้ด ener-scan ราว 60–70% เป็น domain พระเครื่อง/คริสตัล (scan pipeline, amulet, crystal,
moldavite, fengshui, vision-sidecar, deepScan) — ส่วนนี้ **ไม่เอาไป**

ส่วนที่เป็น "แชสซี" ใช้ซ้ำได้ทันที (ประเมิน ~30–40% และเป็นส่วนที่ผ่านศึกมาแล้ว):

| โมดูลเดิม | ใช้ทำอะไรในระบบใหม่ |
|---|---|
| `src/routes/lineWebhook.js` + `handlers` | รับข้อความ LINE ทุก event |
| `lineReply.service` / `linePush429Retry` / `lineSequenceReply` | ส่งข้อความ + retry 429 |
| `conversationStateDualWrite` / `activeStateResolver` / `stateMicroIntent` | จำบริบทบทสนทนา แยก intent |
| `nonScanReply.gateway` + prompts infra | เกต AI ตอบ + persona ต่อร้าน |
| `slipDeterministic` / `slipGate` / `slipImageValidation` | **เช็คสลิปโอนอัตโนมัติ** — จุดขายใหญ่สุด |
| `gbPrimePay.service` / `paymentAccess` / `paymentLifecycleCorrelation` | รับชำระ / ติดตามสถานะจ่าย |
| `entitlement.service` / `freeQuotaPaywall` | นับโควตาข้อความ → คิดเงินรายเดือน |
| `chatQualityDailyReport` + Telegram/LINE push | สรุปยอด+คุณภาพแชทรายวันส่งเจ้าของร้าน |
| `adminKb.routes` + admin dashboard | หลังบ้านให้ร้านใส่สินค้า/ราคา/FAQ |
| workers (delivery/maintenance) + redis + docker | โครง infra เดิมยกมาได้เลย |

**วิธีแยก:** เปิด repo ใหม่ `ener-bot` แล้ว copy โมดูลข้างบนมา ไม่ shared-library กับ ener-scan
(สองระบบจะวิวัฒน์คนละทาง ผูกกันจะพากันพัง) สิ่งที่ต้อง refactor ตอน copy คือ
**ใส่ tenant_id ทุกตาราง/ทุก service** เพราะเดิมเป็น single-tenant

## 2) สถาปัตยกรรม: multi-tenant ตัวเดียว ไม่ deploy แยกต่อร้าน

- 1 deployment, 1 DB — ทุกตารางมี `tenant_id`
- แต่ละร้านเอา LINE OA ของตัวเองมาเสียบ: เก็บ channel access token + secret ต่อ tenant
  webhook URL เดียว แยกร้านจาก destination/channel id
- config ต่อร้าน = template + persona + knowledge base (สินค้า ราคา สต็อก FAQ โปรโมชั่น
  เลขบัญชี/พร้อมเพย์ ค่าส่ง) — AI ตอบจากข้อมูลร้านเท่านั้น (ใช้ kbContext retrieval แบบเดิม)
- ร้านไหนอยากได้ dedicate ค่อยคิดราคาพิเศษทีหลัง

## 3) เทมเพลตเริ่ม 4 แบบ (เลือกตอนสมัคร ปรับแต่งได้)

1. **ร้านเสื้อผ้า/แฟชั่น** — ถามไซซ์ สี สต็อก, ส่งรูปสินค้า, จองตัว, แจ้งโอน+เช็คสลิป, เลขพัสดุ
2. **ร้านขายของออนไลน์ทั่วไป** — แค็ตตาล็อก, รับออเดอร์, สรุปตะกร้า, เช็คสลิป, สถานะจัดส่ง
3. **ร้านบริการ/จองคิว** (คลินิกความงาม นวด ช่างภาพ ติวเตอร์) — ตารางว่าง จองคิว มัดจำ เตือนนัด
4. **ร้านอาหาร/คาเฟ่** — เมนู สั่งล่วงหน้า/pre-order, โปรวันนี้, สรุปออเดอร์เข้าไลน์ครัว

แต่ละเทมเพลต = system prompt + ชุด flow ที่เปิด/ปิดได้ + ฟอร์มข้อมูลที่ร้านต้องกรอก
ทุกเทมเพลตมี: ปุ่ม "คุยกับแอดมิน" (human handover — สำคัญมาก ห้ามให้ AI ตันแล้วเงียบ),
สรุปยอดรายวัน 20:00 เข้า LINE เจ้าของ (ยอดขาย จำนวนออเดอร์ จำนวนแชท คำถามที่ตอบไม่ได้)

## 4) ราคา — อิงต้นทุนจริงจาก cost audit 13 ส.ค.

ต้นทุน AI ตอบแชท (ไม่มี vision pipeline แบบ scan) ถ้าใช้โมเดลระดับ GPT-4.1-mini/Gemini Flash
+ prompt สั้นต่อร้าน ≈ **0.05–0.25 บาท/ข้อความตอบ** (เผื่อ retrieval + rewrite แล้ว)
เช็คสลิป 1 ครั้ง ≈ 0.3–0.5 บาท (มี vision call)

ตัวอย่าง tier (กำไรขั้นต้น >80% ทุกชั้น):

| แพ็กเกจ | AI ตอบ/เดือน | ราคา/เดือน | หมายเหตุ |
|---|---:|---:|---|
| Starter | 500 | 590 บาท | ร้านเล็ก เริ่มลอง |
| Pro | 2,000 | 1,490 บาท | + เช็คสลิปไม่จำกัด |
| Business | 6,000 | 3,490 บาท | + หลาย OA / หลายสาขา |
| เกินแพ็กเกจ | — | 0.50 บาท/ข้อความ | หรือ auto-upgrade |

เคล็ดสำคัญ: **คำตอบ deterministic ไม่นับโควตา** (เมนูปุ่มกด, ราคาแบบตรงตัว, สถานะออเดอร์)
นับเฉพาะที่ AI generate จริง → ต้นทุนเราต่ำลง ลูกค้ารู้สึกคุ้ม และเรามีเกม optimize เองได้
ใช้ `entitlement.service` เดิมนับได้เลย + ใส่ `callSite` logging ตาม audit เพื่อรู้ margin ต่อร้านจริง

## 5) ต้องสร้างใหม่ (ไม่มีในของเดิม)

1. **Tenant onboarding** — หน้า/LIFF สมัคร: เสียบ LINE OA token, เลือกเทมเพลต, กรอกข้อมูลร้าน
2. **Merchant dashboard** — ดูแชทย้อนหลัง, แก้ KB เอง, ดูยอดใช้โควตา, ดาวน์โหลดสรุปยอด
3. **Billing รายเดือน** — เริ่มง่าย ๆ: แจ้งเตือนต่ออายุ + จ่ายพร้อมเพย์ + เช็คสลิปด้วยระบบตัวเอง
   (dogfood จุดขายตัวเอง) ค่อยทำ recurring GB Prime Pay ทีหลัง
4. **Order object กลาง** — ตะกร้า/ออเดอร์/สถานะ (ของเดิมไม่มี เพราะ ener ขาย access ไม่ใช่สินค้า)
5. **Human handover** — ปิด AI ชั่วคราวเมื่อแอดมินร้านเข้ามาตอบ แล้วเปิดคืนอัตโนมัติ

## 6) ความเสี่ยง / กติกา

- **AI ตอบราคา/สต็อกผิด = ร้านเสียเงินจริง** → AI ห้าม generate ตัวเลขเอง ต้องดึงจาก KB เท่านั้น
  ตอบไม่ได้ให้ส่ง handover ไม่ใช่เดา (มี validator layer แบบ `conversationOutputValidator` เดิม)
- ตลาดนี้มีคู่แข่ง (chatbot LINE OA เจ้าอื่น) — จุดต่างของเรา: ตอบเป็นธรรมชาติแบบมีบริบท,
  **เช็คสลิปอัตโนมัติ**, สรุปยอดรายวัน, ตั้งค่าเป็นภาษาไทยง่าย ไม่ต้องเขียน flow เอง
- อย่าให้กระทบ ener-scan: คนละ repo คนละ deploy คนละ OpenRouter key (attribution แยกตาม audit)
- PDPA: ข้อมูลแชทลูกค้าของร้านเป็นของร้าน ต้องมีข้อตกลง + ลบได้

## 7) เฟสเสนอ

## สังเคราะห์รอบ 1 — คำตอบ AI 2 ตัว + คำวิจารณ์พรอมพ์ (14 ส.ค. 2026)

### คำวิจารณ์พรอมพ์ (จาก AI ตัวที่ 3) — รับเกือบทั้งหมด

รับ: เลือก vertical เดียวก่อน · เปลี่ยนคำโฆษณา ("ตอบถูกแน่/เหมือนคน 100%/ห้ามตัน")
เป็น KPI วัดได้ (hallucination rate, booking success, unresolved rate) · handoff ไม่ใช่
ความล้มเหลว จุดขายคือ "ส่งต่อไร้รอยต่อ ลูกค้าไม่ต้องเล่าใหม่" · tool ต้องระบุ
source of truth / read-write / confirm / idempotency / failure behavior ·
multi-tenant security (isolation, RBAC, audit, prompt injection, PDPA) ·
unit economics ต้องรวมค่า LINE API + onboarding + support ไม่ใช่แค่ค่า AI
ข้อแม้เดียว: พรอมพ์ฉบับปรับยาว 11 หัวข้อ — โมเดลส่วนใหญ่จะตอบตื้นลงถ้ายิงทีเดียว
→ **ใช้ฉบับปรับ แต่แบ่งยิง 2 ท่อน**: A(ข้อ 1–6 product/design) + B(ข้อ 7–11 arch/economics/market)

### ฉันทามติจาก AI 2 ตัว (ตรงกันทั้งคู่ = เชื่อได้)

- MVP: จอง/เลื่อน/ยกเลิกนัด + สต็อก-ราคาจาก source จริง + ออเดอร์ + เช็คสลิป + สรุปรายวัน + KB admin
- Tool set ลงตัวที่ ~15 functions ตรงกันเกือบทุกตัว (check_availability, book/reschedule/
  cancel, get_booking_list, get_product_info/check_stock, create_order, get_order_status,
  verify_slip, get_payment_info, search_kb, handoff_to_human พร้อม context, collect_customer_info)
- Integration เริ่มแค่ 3: **Google Sheets (SME ไทยใช้เป็น DB จริง) + Google Calendar + พร้อมเพย์/สลิป**
  ขนส่ง/POS/Shopee = เฟสหลัง
- No-dead-end สูตรเดียวกัน: ถามกลับ → เสนอทางเลือก → ทำรายการให้ → handoff เนียนพร้อมสรุปบริบท

### ไอเดียใหม่ที่รับเข้าแผน

1. **Silent mode**: แอดมินเข้ามาตอบ → bot เงียบอัตโนมัติ (กันตอบชน) + SLA 5 นาที ไม่มา bot follow-up
2. **Policy engine มัดจำ/เลื่อนนัด ต่อร้าน**: เลื่อนครั้งแรกฟรี, ครั้ง 2 เตือน, ครั้ง 3 มัดจำใหม่,
   no-show → ต้อง prepay ครั้งหน้า, เลื่อนใกล้เวลา (<2 ชม.) มีเงื่อนไข
3. Confidence ต่ำ → เมนูตัวเลือก แทนการเดา
4. check_stock สดทุกครั้งก่อนตอบ + cache TTL สั้น
5. reschedule = atomic (cancel เก่า + create ใหม่ พร้อม idempotency)
6. LLM adapter สลับ provider ได้ · ทดลองฟรี 14 วัน
