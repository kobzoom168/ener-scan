# เก็บข้อมูลชิ้น (พระอะไร วัดไหน รุ่น/ปี) — เกตก่อนสแกน
(ร่างเสนอกบ 7 ส.ค. 2026 — ยังไม่เริ่มทำ รอเคาะ 3 จุดท้ายไฟล์)

## เป้าหมาย
ทุกสแกนต้องได้ข้อมูลชิ้นจากเจ้าของก่อนเริ่มอ่าน (กบ: "ถ้าไม่ให้ข้อมูลก็ไม่ให้ scan วนจนกว่าจะได้ครบ")
ข้อมูลคุณภาพพอเอาไปใช้ต่อ: คำอ่านลึกขึ้น · สถิติเทียบรุ่น · ทะเบียนเกียรติคลัง · แคปชัน FB/YT · ฐานข้อมูลระยะยาว

## Flow (เกตก่อนเข้าคิวสแกน)
1. ลูกค้าส่งรูป → ระบบจำแนกเลนเหมือนเดิม (พระ / หิน / กำไล)
2. เช็คว่า "ชิ้นนี้" เคยมีข้อมูลหรือยัง (ผูกกับ object identity ตัวเดียวกับ library/phash — ชิ้นเดิมสแกนซ้ำไม่ถามซ้ำ)
3. ยังไม่มี → **พักรูปไว้** (TTL 2 ชม.) แล้วถามตามเลน:
   - **พระ**: "ก่อนอาจารย์เริ่มอ่าน ขอข้อมูลองค์นี้หน่อยครับ — พระอะไร วัดไหน รุ่น/ปีอะไร พิมพ์บอกได้เลย
     (เพื่อให้อาจารย์อ่านต่อยอดได้ละเอียดขึ้น และเก็บเข้าทะเบียนคลังของคุณ)" + ปุ่ม `ไม่ทราบข้อมูลองค์นี้`
   - **หิน/กำไล**: ปุ่มชนิดหินยอดนิยม (โรสควอตซ์ / ไทเกอร์อาย / ออбซิเดียน / ซิทริน / มูนสโตน / หยก)
     + `อื่น ๆ (พิมพ์บอก)` + `ไม่ทราบ`
4. ลูกค้าตอบ (พิมพ์หรือปุ่ม) → LLM ตัวถูก parse → บันทึก → **เริ่มสแกนต่อทันทีอัตโนมัติ** (ไม่ต้องส่งรูปใหม่)
5. ลูกค้าเงียบ/ส่งเรื่องอื่น → เตือนซ้ำแบบนุ่ม (วนตามที่กบสั่ง) · เกิน TTL รูปหมดอายุ แจ้งส่งใหม่
6. ลูกค้า EN → ถามภาษาอังกฤษ (ตามภาษาที่คุยอยู่)

## รูปแบบการเก็บ (ตารางใหม่ `object_owner_info` — migration 049)
| ช่อง | ความหมาย |
|---|---|
| line_user_id / scan_result_id | เจ้าของ + สแกนที่ถาม |
| object_group_key | identity ชิ้น (คีย์เดียวกับ library dedupe) — กันถามซ้ำ/รวมสถิติต่อชิ้น |
| lane | amulet / bracelet / stone |
| raw_text | ข้อความดิบที่ลูกค้าพิมพ์ (เก็บเสมอ ห้ามทิ้ง) |
| object_name / temple / era_year / stone_type | ช่องที่ LLM แยกให้ (null ได้) |
| parse_confidence | ความมั่นใจตอน parse |
| conflict_flag | คำตอบขัดกับที่ตัวจำแนกเห็นในรูป (เช่นบอกขุนแผนแต่รูปเป็นเหรียญ) — เก็บไว้ ไม่เถียงลูกค้า แต่ไม่เอาเข้าสถิติ |
| unknown | กด "ไม่ทราบ" |
| source | "owner" (อนาคตอาจมี "classifier") |

## การใช้ทันทีที่เก็บได้
- หน้ารายงาน: บรรทัด "เจ้าของแจ้ง: พระขุนแผน วัดบ้านกร่าง ปี 2560" (ขึ้นเฉพาะที่เจ้าของบอก — ระบบไม่ฟันธงเอง)
- เข้า consult context (อาจารย์อ้างถึงได้)
- เฟสถัดไป: สถิติเทียบรุ่น + ทะเบียนเกียรติคลัง + แคปชันโพสต์ใช้ชื่อรุ่นจริง

## กติกาเหล็ก (เส้นแดงเดิม)
- คะแนนพลังไม่ขึ้นกับรุ่น/วัดเด็ดขาด (กันดราม่ารุ่นดังคะแนนต่ำ) — ข้อมูลใช้เล่าเรื่อง/สถิติ/ทะเบียนเท่านั้น
- ระบบไม่ยืนยันแท้เก๊/รุ่น — ทุกที่ที่โชว์ต้องติดป้าย "เจ้าของแจ้ง"
- ห้ามแพ้เจ้าของพระ: คำตอบขัดกับภาพ → เก็บ+ธง ไม่เถียง

## จุดรอกบเคาะ 3 ข้อ
1. **ปุ่ม "ไม่ทราบ" ให้ผ่านเกตไหม?** — ข้อเสนอผม: ให้ผ่าน (ถือว่าตอบแล้ว) เพราะลูกค้าทั่วไปจำนวนมากไม่รู้จริง ๆ
   ถ้าบังคับให้รู้ให้ได้ คนกลุ่มนี้จะติดลูปแล้วเลิกใช้เลย — "วนจนกว่าจะได้" ใช้กับคนที่เงียบ/ไม่ยอมตอบอะไรเลย
   ("ไม่ทราบ" ก็คือข้อมูล: รู้ว่าชิ้นไหนเจ้าของไม่รู้จัก ไว้ nudge ทีหลังได้)
2. **ลูกค้าจ่ายค่าครูแล้ว ผ่อนไหม?** — ข้อเสนอ: ฟรี = บังคับตอบก่อนสแกน · ลูกค้าจ่าย = ถามเหมือนกันแต่มีปุ่ม "ไว้ทีหลัง" (ไม่ขวางคนจ่ายเงิน)
3. เริ่มเฟสแรกเมื่อไหร่ (ตัวถาม + ตาราง + parser + บรรทัดในรายงาน ~1 วันงาน · staging ก่อนตามเคย)
