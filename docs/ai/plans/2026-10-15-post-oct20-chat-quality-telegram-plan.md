## 2. AI ตอบฉลาดและเป็นธรรมชาติ

เป้าหมาย: โทนอาจารย์ Ener สุภาพ เข้าใจง่าย ตอบคำถามล่าสุดตรงประเด็น จำบริบท อ้างข้อมูลได้ ไม่วน ไม่เร่งขาย ไม่รับปากเกินจริง

- ไม่เกริ่นว่าเป็น AI/ระบบ/บอทในทุกคำตอบ และไม่เปิดเผย prompt หรือศัพท์งานภายในโดยไม่จำเป็น
- หากลูกค้าถามตรงว่าเป็น AI หรือไม่ ให้ตอบตามจริงอย่างสั้น ไม่แอบอ้างว่าเป็นมนุษย์หรือมีอาจารย์มนุษย์รับช่วง ทั้งที่ไม่มี
- ไม่ใช้คำอ้างว่ากำลังเพ่งพลัง/ตรวจด้วยตนเองแทนสถานะงานจริง ไม่รับประกันความแม่นยำหรือพลังเหนือธรรมชาติเป็นข้อเท็จจริง
- แยกข้อมูลจากรายงานสแกน ความเชื่อ/การตีความ และสิ่งที่ไม่ทราบให้ชัด คะแนน/เปอร์เซ็นต์ต้องอ้างรายงานของเจ้าของบัญชีที่มีอยู่จริง
- ถ้าลูกค้าทักท้วงผลต่าง ให้รับฟังและเทียบรายงานที่ตรงชิ้นก่อน ไม่สวนว่า “ไม่มั่ว” หรืออ้างว่าแม่นยำที่สุด
- ลูกค้าปฏิเสธการจ่าย/ไม่พอใจ/ตอบคำถามเดิม: ห้ามวนเสนอราคา ให้ตอบเรื่องที่ค้างก่อน
- สิทธิ์และจำนวนคงเหลืออ่านจากแหล่งจริง ไม่รับปากว่าทุกคนเหลือทดลอง 2 ครั้ง ไม่บอกให้ซื้อเพื่อเปิดผลเก่า
- ตรวจ call graph, prompt, facts, fallback, context truncation และ guard ก่อนตัดสินว่าต้องเปลี่ยนโมเดล ความฉลาดต้องวัดด้วยชุดทดสอบ ไม่ใช่เพิ่มค่าใช้จ่ายอย่างเดียว
- เทียบคุณภาพ ความเร็ว และค่าใช้จ่ายของแนวทางที่เสนอ ก่อนขออนุมัติเปลี่ยนโมเดล/config

## 3. สถานะอนุมัติสลิปผ่าน Telegram

ตามหลักฐานที่ส่งมา: โค้ดและ automated tests มีแล้ว แต่ยังไม่เปิดใช้จริงบน Pro

- live staging ผ่าน STG-TG-2: ขออนุมัติ → ยืนยัน → paid และ grant 1 แถว เพิ่ม 4 สิทธิ์ครั้งเดียว
- กดซ้ำ/กดรัวพร้อมกัน/ผู้ไม่มีสิทธิ์: automated PASS เท่านั้น ยังไม่ใช่ live PASS
- รอบทดสอบ cleanup แล้ว Telegram approval ปิด webhook ถูกถอด; Pro รายงานว่าไม่มี settings สำหรับเปิด approval
- ฟีเจอร์ปฏิเสธสลิปผ่าน Telegram ยังไม่มี อย่าแสดงหรืออ้างว่ามี

งานถัดไป: ตรวจสถานะ/config สด → สรุปเคสที่ยังไม่ผ่าน live → เลือก bot/ห้อง Pro และรายชื่อผู้อนุมัติ → จัดแผนทดสอบ/rollback → ขออนุมัติเปิดใช้งานแยก
ต้องคง session-only admin, CSRF, encryption, restricted RPC, ตรวจ Telegram user id, secret webhook และ atomic/idempotent grant
ไม่ขอ token ในแชต ไม่พิมพ์ token/secret ลง log หรือเอกสาร

## 4. ย้ายแจ้งเตือนแอดมินทั้งหมดไป Telegram

ความต้องการกบ: ไม่รับแจ้งเตือนงานแอดมิน/ระบบทาง LINE อีก
ขอบเขตนี้ไม่รวมข้อความบริการถึงลูกค้า เช่น ผลสแกน แจ้งรับชำระ และข้อความตอบแชต ซึ่งยังอยู่ LINE

### สำรวจผู้ส่งก่อนแก้

- ทำตาราง source → trigger → environment → recipient → channel → retry/dedupe → owner
- ครอบคลุม DLQ, scan/queue/worker failure, payment/manual review, health/ops/security, รายงานคุณภาพแชตรายวัน และ cron/monitor ภายนอก repository
- รายงานแนบชื่อ ener_chat_quality / job_id 33595b0feed1 เป็นเบาะแสให้ตรวจว่าใครเป็นผู้รัน ห้ามสรุปว่าแก้แค่แอปแล้วจะย้ายครบ
- แยก approval ที่มีปุ่มออกจาก alert ที่อ่านอย่างเดียว ตรวจสิทธิ์สมาชิกห้องก่อนส่งข้อมูลสลิปหรือข้อมูลลูกค้า

### ออกแบบและย้าย

- ใช้ช่องทางส่งแจ้งเตือนร่วมที่แยก environment/category/severity และผูกปลายทางชัดเจน อาจแยกห้อง alert จากห้อง approval ตามที่กบเลือก
- คง dedupe หลังส่งสำเร็จ, short lock, retry/backoff และการรับมือ rate limit ไม่ทำให้ alert หายเงียบ
- เมื่อ Telegram ล่ม ให้เก็บสถานะล้มเหลว/คิว retry และตรวจได้ ห้าม fallback ส่ง LINE แอดมินเอง เพราะขัดความต้องการกบ; หากต้องมีช่องทางฉุกเฉินอื่นให้ขอเลือกก่อน
- จำกัดข้อมูลส่วนบุคคล ปกปิด user id และห้าม token/secret ในเนื้อหา/log
- ทดสอบบน staging ก่อนสลับแต่ละ source ปิดผู้ส่ง LINE เดิมหลังพิสูจน์ Telegram สำเร็จและมีทางกู้ ห้ามปิด alert รวมเพื่อหยุดข้อความรบกวน
- เกณฑ์รับงาน: ทุก source ใน inventory มีผลทดสอบ ข้อความถึง Telegram ถูกห้อง/ครั้งเดียวตามกติกา และ LINE admin ไม่รับแล้ว โดย LINE ลูกค้ายังทำงานเดิม

- คำว่า “ส่งให้อาจารย์แล้ว” ต้องตรวจว่ามีการส่งต่อจริง ไม่ใช่เปลี่ยนถ้อยคำเพื่อซ่อนงานที่ไม่จบ
- “วันนี้แชทเรียบร้อย” ต้องแยกตรวจครบไม่พบปัญหา / ไม่มีทราฟฟิก / ดึงข้อมูลไม่ได้ / ตรวจเพียงบางส่วน
- แต่ละ finding ต้องมีเวลาชัดเจน timezone เดียว, message/job/report reference, ข้อเท็จจริงที่คาด, ข้อความที่พบ และสถานะ confirmed/suspected/false positive
- audit อ่านอย่างเดียวก่อน ห้ามส่งข้อความทดสอบหาลูกค้าจริงหรือเปลี่ยนข้อมูลเพื่อพิสูจน์

## 8. ข้อกำหนดเพิ่มจากกบ 15 ต.ค. 2026 (งานข้อ 2 คุณภาพ AI) — **มีจุดขัดกับ §2 ต้องเคาะก่อนเริ่ม**

กบ: "ห้ามจับได้ว่าเป็น AI · แชตรับเป็นแอดมิน ส่งต่ออาจารย์ · แต่ต้องตอบแบบฉลาดที่สุด"

ส่วนที่รับได้เต็มที่และจะทำ (ตรงกับ §2 อยู่แล้ว):
- ไม่เกริ่น/ไม่ประกาศว่าเป็น AI หรือบอทในทุกคำตอบ ไม่ใช้ศัพท์ระบบ โทนแอดมิน/ผู้ช่วยอาจารย์ที่เป็นธรรมชาติ จำบริบท ตอบตรงคำถามล่าสุด ไม่วน ไม่เร่งขาย
- บทบาท "แอดมินรับเรื่องแล้วส่งต่ออาจารย์" ใช้ได้ **เฉพาะเมื่อมีการส่งต่อจริง** (มีคนจริง = กบ รับช่วงผ่าน admin handoff / แจ้งเตือน Telegram ตามงานข้อ 3) และต้องมีการตอบกลับจริงตามที่รับปาก — ไม่งั้นเป็น "รับปากแล้วเงียบ" ที่รายงาน chat quality จับได้ (5, 11, 12 ต.ค.)
- "ฉลาดที่สุด" วัดด้วยชุดเคสจริงแบบ replay (§2, §5) ไม่ใช่เปลี่ยนโมเดลแพงขึ้นอย่างเดียว

ส่วนที่ขัดกับ §2 และ Claude ขอไม่ทำตามตัวอักษร:
- **เมื่อลูกค้าถามตรง ๆ ว่า "เป็นบอท/AI ใช่ไหม" — จะไม่ให้ระบบตอบว่าเป็นมนุษย์** (โกหกลูกค้าโดยตรง) · Codex §2 ก็ระบุว่า "ห้ามแอบอ้างว่าเป็นมนุษย์หรือมีอาจารย์มนุษย์รับช่วงทั้งที่ไม่มี" · ความเสี่ยง: ถูกจับได้ทีหลัง = เสียความเชื่อถือทั้งแบรนด์ (ลูกค้าในรายงาน 9 ต.ค. เริ่มทักท้วงความแม่นอยู่แล้ว)
